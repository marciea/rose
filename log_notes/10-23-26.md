DNSmasq DNS&DHCP is in use alongside Unbound following the configuration examples [here in the opnsense docs](https://docs.opnsense.org/manual/dnsmasq.html#configuration-examples) but obviously replacing values like the domain for `rose.internal` and the reverse lookup.

>[!quote]
*"We will use Unbound as primary DNS server for our clients, and only forward some internal zones to Dnsmasq which manages the hostnames of DHCP registered leases. This requires Dnsmasq to run with a non-standard port other than 53."*

>Unbound is the DNS resolver my clients use. It handles normal DNS lookups and forwards queries for `rose.internal` to dnsmasq. Dnsmasq provides DNS and DHCP, and answers those internal queries using its configured host records and DHCP information. For example, to reach Wiki.js by name, I need a dnsmasq record or DHCP-associated name that maps `wiki.rose.internal` to the Wiki.js server’s IP address. Once that record is in place and my client is using Unbound for DNS, I can browse to `wiki.rose.internal`. The forwarding rule directs the query to dn1smasq; it does not create the `wiki` record on its own.

| Option              | Value                     |
| ------------------- | ------------------------- |
| **Domain**          | `rose.internal`           |
| **Server IP**       | `127.0.0.1`               |
| **Server Port**     | `53053`                   |
| -----------         | ----------                |
| **Domain**          | `20.168.192.in-addr.arpa` |
| **Server IP**       | `127.0.0.1`               |
| **Server Port**<br> | `53053`                   |
If I were to ever serve another separate zone then I would need to add it as another entry; essentially what is done for the "guest.internal" zone in the docs example.

Test for  functionality: 
```bash
dig http.cat @192.168.20.1 -p 53
```
